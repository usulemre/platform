# Feature Service (`feature_service`)

> **Phase 2.4 — Feature Service (implemented).** Governs the complete lifecycle of quantitative
> research features — declarative, PIT-bound, leakage-clean, provenance-bearing, versioned artifacts
> derived from datasets. The institutional source of truth for feature creation, lineage, validation
> coordination, and lifecycle. **Orchestration/model, interfaces only** — no factor calculation, no
> feature-engineering implementation, no ML, no statistics, no persistence, no infrastructure, no API.

## Purpose

Realize the feature capability of the **Research Intelligence Layer** over the **Data Platform**
(Architecture V2 §5.5/§5.8). It connects the Data Platform, Research, Dataset, and Experiment
services with downstream Backtesting/Signal/Portfolio components (by identity) and integrates with
the **Feature Registry**. It reuses the Phase-1/2 foundations rather than duplicating them.

## Authority & boundaries

The Feature Service **orchestrates and records**; it **never computes features/factors**, **never
runs ML or statistics**, **never adjudicates significance** (CP-5, AI-2), and **never exposes
look-ahead/OOS** (PIT-3, AD-3, `P2-07`). Acceptance requires the deterministic **Leakage Harness**
to pass (FA-2, `P2-03`); every feature carries provenance (FA-3) and is versioned/immutable (FA-4);
computation is always through the as-of path (FA-1, PIT-3).

## What is here (Phase 2.4)

20 modules, each a subpackage with its own `README.md`:
`model` · `status` · `lifecycle` · `versioning` · `classification` · `ownership` · `metadata` ·
`dependencies` · `lineage` · `registration` · `discovery` · `validation_coordination` ·
`registry_integration` · `approval` · `management` · `policies` · `specifications` · `events` ·
`errors` · `repositories`.

- **Canonical models** (across `model`/`versioning`/`dependencies`/`lineage`/`metadata`/`ownership`/
  `classification`/`status`): `Feature` (aggregate, reuses `core_domain.AggregateRoot`),
  `FeatureIdentifier`, `FeatureMetadata`, `FeatureDefinition`, `FeatureFormulaReference`,
  `FeatureOwner`, `FeatureStatus`, `FeatureClassification`, `FeatureVersion`, `FeatureDependency`,
  `FeatureLineage`, `FeatureEvidence`, `FeatureValidationReference`.
- **Lifecycle:** `PROPOSED → REGISTERED → IMPLEMENTED → VALIDATING → APPROVED → ACTIVE → DEPRECATED →
ARCHIVED`, supporting revision, superseding, rollback (governed reactivation), and retirement;
  branching creates a new versioned lineage (RL-1); skips forbidden (fail-closed).
- **Domain events:** `FeatureRegistered`, `FeatureVersionCreated`, `FeatureValidated`,
  `FeatureApproved`, `FeatureActivated`, `FeatureDeprecated`, `FeatureArchived`,
  `FeatureDependencyAdded`, `FeatureLineageUpdated`.

## Integration (by identity / foundation)

- **Data Platform / Dataset Service** — dataset references (`FeatureDefinition.dataset_inputs`, `dependencies`).
- **Research Service / Experiment Service** — research context & experiment references (by identity).
- **Validation Foundation** (`platform_validation`) — `validation_coordination` orchestrates structural
  validation; the deterministic **Leakage Harness** (`core_domain.feature.LeakageHarness`) gates acceptance.
- **Feature Registry** — `registry_integration` (`FeatureRegistryPort`): register-before-use,
  immutable/versioned entries, Marketplace publication.

## Boundary rules (verified)

- **Deterministic, technology-independent:** code scan **CLEAN** — no `scipy`/`numpy`/`pandas`/
  `statsmodels`/`sklearn`/`torch`/`tensorflow`, no `def compute`/`def calculate`, no persistence/infra.
- **Immutable, versioned, traceable:** all models/records/events are `frozen` dataclasses (runtime
  `FrozenInstanceError`); `FeatureVersion` content-addressed; `FeatureLineage` gives full traceability
  with downstream invalidation (CP-6/DP-2); repositories append-only.
- **Governance encoded:** `LeakageClearancePolicy`/`LeakageNotCleared` (FA-2), `AsOfComputationPolicy`/
  `LookAheadComputation` (PIT-3), `ProvenanceRequiredPolicy` (FA-3), `ImmutabilityPolicy` (FA-4),
  `FeatureSelfAdjudication` (CP-5), `IsolationBarrierBreach` (AD-3/P2-07).
- **Compiles and imports cleanly**, 20 modules, no circular dependencies.
