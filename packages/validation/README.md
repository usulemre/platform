# validation (package) — `platform_validation`

> **Phase 1.6 — Validation Foundation (implemented).** The institutional, reusable, composable
> **structural** validation framework used across every domain. **Abstractions only** — no
> validation algorithms, no statistical tests, no business rules, no persistence, no infrastructure.

> ⚠️ **This is NOT statistical validation.** Statistical significance, deflation, PBO,
> purged/embargoed CV, one-shot holdout, replication, and capital-eligibility are the **exclusive**
> domain of the deterministic Validation engine (RB-01 · STAT, RB-04 · VAL, `P2-*`, Architecture V2
> §5.6). This framework **never** asserts significance (AI-2) and issues **no** verdict about
> whether an alpha is real — a `FAILED` result here is a _structural_ outcome, not a scientific one.

## Purpose

Provide the common structural/rule-based validation abstractions (model, rules, specifications,
policies, results, reports, pipeline, registry, errors) that datasets, experiments, features,
signals, strategies, portfolios, workflows, configuration, and governance all reuse — deterministic,
composable, and auditable.

## What is here (Phase 1.6)

11 modules, each a subpackage with its own `README.md`:
`model` · `context` · `policy` · `rule` · `specification` · `result` · `report` · `metadata` ·
`registry` · `pipeline` · `errors`.

Key objects: `Validation`, `Validator`, `ValidationContext`, `ValidationRule`, `ValidationPolicy`,
`ValidationSpecification`, `ValidationResult`, `ValidationFailure`, `ValidationSuccess`,
`ValidationReport`, `ValidationMetadata`, `ValidationRegistry`.

## Taxonomy & lifecycle

- **11 categories** (`model.ValidationCategory`): Dataset · Research · Experiment · Feature · Signal
  · Strategy · Portfolio · Risk · Workflow · Configuration · Governance.
- **Lifecycle** (`model.ValidationLifecycle`): `CREATED → PRE_VALIDATION → VALIDATING → PASSED /
FAILED → ARCHIVED`, with revalidation transitions back to `PRE_VALIDATION`.
- **Modes** (`model.ValidationMode`): `FULL · PARTIAL · INCREMENTAL · COMPOSITE · REVALIDATION`.

## Boundary rules (verified)

- **Deterministic:** no ambient time/RNG; `as_of` is supplied on the context (CS-3).
- **Composable:** `ValidationSpecification` + `CompositeSpecification` (AND/OR/NOT) and a multi-stage
  `ValidationPipeline` (optional stages = partial validation) — reuse and composition are first-class.
- **Technology/framework-independent:** only `__future__`, `dataclasses`, `enum`, `typing` + the
  contract kernel; a scan confirms **no** statistical/algorithm libraries (`scipy`/`numpy`/
  `statsmodels`/`sklearn`/`math`).
- **Immutable & auditable:** every object is a `frozen` dataclass (runtime `FrozenInstanceError`);
  reports and metadata carry owner/version/lifecycle for audit (CP-7).
- **No algorithms / statistical tests / business rules / persistence / infrastructure:**
  validator/rule/spec/pipeline/registry methods are `...` placeholders.
- **Compiles and imports cleanly**, 11 modules, no circular dependencies (the `Validator` interface
  in `model` references `context`/`result` only under `TYPE_CHECKING`).
