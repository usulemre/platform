# workflow-engine (package) — `workflow_engine`

> **Phase 1.3 — Workflow Engine Foundation (implemented).** The technology-independent Workflow
> Control Layer abstractions: how workflows are represented, transitioned, validated, approved,
> escalated, executed, and audited. **Abstractions only** — no workflow logic, no orchestration,
> no infrastructure, no persistence, no AI. Workflows **orchestrate; they never adjudicate**
> (WCON-2, AV2-18).

## Purpose

Define the canonical, reusable, deterministic workflow-engine model that realizes the Tier-5
Workflow Contracts (Architecture V2 §5.4). Every gate delegates to a deterministic engine or a
human approver; the engine itself decides nothing. The concrete engine implementation (Temporal,
per the [TDR](../../docs/architecture/technology_decision_record.md) §15) plugs in behind these
interfaces.

## What is here (Phase 1.3)

15 modules, each a subpackage with its own `README.md`:

- **`state/`** — the canonical `WorkflowState` lifecycle and `StateCategory`, terminal/failure sets.
- **`transition/`** — `WorkflowTransition`, `TransitionKind`, `TransitionSpec` (named pre/postconditions).
- **`state_machine/`** — the canonical machine: `CANONICAL_TRANSITIONS`, `FORBIDDEN_TRANSITIONS`
  (stage-skips), `APPROVAL_POINTS`, `VALIDATION_GATES`, `ROLLBACK_POINTS`, `TERMINAL_STATES`, and the
  fail-closed `StateMachine` interface.
- **`definition/`** — `Workflow`, `WorkflowDefinition`. **`instance/`** — `WorkflowInstance` (immutable snapshot).
- **`context/`** — `WorkflowContext`. **`metadata/`** — `WorkflowMetadata` (references the Tier-5 contract id).
- **`validation/`** — `WorkflowValidation` + `WorkflowValidationGate` (delegates to a deterministic engine).
- **`approval/`** — `WorkflowApproval` + `WorkflowApprovalGate` (human decides, with counter-sign).
- **`escalation/`** — `EscalationPath` + `WorkflowEscalation`.
- **`execution/`** — `WorkflowEngine`, `StageRunner`, `Compensator` (saga/rollback), `WorkflowExecution`.
- **`events/`** — the workflow lifecycle events. **`audit/`** — `WorkflowAuditRecord`, `WorkflowAuditTrail`, `RunLedger`.
- **`policies/`** — `StateMachinePolicy`, `StageSkipPolicy`, `GateOwnershipPolicy`. **`results/`** — `WorkflowResult`, `WorkflowError`.

## Canonical lifecycle

`PROPOSED → REGISTERED → READY → RUNNING → VALIDATING → APPROVED → COMPLETED`, with failure/holding
states `FAILED · REJECTED · BLOCKED · ESCALATED · SUSPENDED · RETIRED`. The validation gate
(`RUNNING→VALIDATING`) and approval point (`VALIDATING→APPROVED`) are explicit; stage-skips such as
`RUNNING→COMPLETED` are declared **forbidden** (WFC-3/16/17). Any transition not in the canonical set
is rejected fail-closed.

## Workflow events

`WorkflowCreated · WorkflowStarted · WorkflowPaused · WorkflowResumed · WorkflowValidated ·
WorkflowApproved · WorkflowRejected · WorkflowCompleted · WorkflowFailed · WorkflowEscalated`
(each subclasses the `platform_contracts` `Event` envelope).

## Boundary rules (verified)

- **Deterministic:** no ambient time/RNG; the state machine is pure data + interfaces; time/as-of
  are supplied on `WorkflowContext` and event envelopes (CS-3).
- **Framework/technology-independent:** standard library + the `platform_contracts` kernel only
  (`Id`, `ActorRef`, `Event`, `SchemaVersion`, `VersionTag`); no orchestration engine, no infra.
- **Immutable:** every definition/instance/record/event is a `frozen` dataclass (runtime
  `FrozenInstanceError`); transitions produce new instance snapshots (append-only history).
- **No workflow logic / orchestration / persistence / AI:** gate and engine methods are `...`
  placeholders; the engine orchestrates and never adjudicates (WCON-2, AV2-18).
- **Compiles and imports cleanly**; no circular dependencies (modules depend only downward toward
  `state`/`context`/the contract kernel).
